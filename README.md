# Synapse · 언어와 문화 맥락을 연결하는 메신저

`jiwon100022/pp`의 React/TypeScript 앱입니다. 기존 시연 화면을 유지하면서 가입, 언어별 라운지, 실제 사용자 간 채팅과 AI 처리 서버를 추가했습니다.

## 기능

- 이름·국가·사용 언어로 간단한 가입, 프로필 수정, 로그아웃
- 국가와 언어를 독립적으로 선택: 한국어 / 영어 / 일본어 / 중국어 번체
- 가입 언어의 라운지와 Global Lounge 자동 참여, 언어별 UI·날짜·시간
- 멤버를 선택해 새 채팅방 생성, 채팅방·메시지 검색, 읽지 않은 메시지 표시
- 원문과 기본 번역·문화 맥락 번역 비교, 유행어·사투리·관용어·예절·높임말 분석
- 문화 표현 설명, 오해 가능성이 높은 표현의 대안 제시, 표시 수준 설정
- 현재 채팅방의 실제 최근 대화 요약, 명시된 결정·할 일 표시
- 대화 JSON 내보내기, 모바일·데스크톱 반응형

## 실행 모드

| 모드 | 저장 | 다른 사용자와 채팅 | 번역·요약 |
|---|---|---|---|
| 정적 사이트 / GitHub Pages | 해당 브라우저 localStorage | 지원 안 함 (예시 사용자·대화 포함) | 등록된 예문 번역, 문화 표현 규칙, 최근 메시지 발췌 |
| Node 서버, API 키 없음 | 서버 `data/chat.json` | 실시간 SSE | 등록된 예문 번역, 문화 표현 규칙, 최근 메시지 발췌 |
| Node 서버, API 키 설정 | 서버 `data/chat.json` | 실시간 SSE | 임의 문장 AI 번역·문화 분석, 실제 대화 AI 요약 |

AI 미연결 상태에서는 임의 문장을 번역한 것처럼 표시하지 않습니다. 메시지는 원문으로 전달되며 제한이 표시됩니다. 발췌 모드는 결정 사항을 추측하지 않습니다. AI 실패 시 원문과 오류 상태를 유지합니다. 작성 중 힌트는 로컬 규칙으로 처리하고 전송한 메시지의 전체 문화 분석을 서버에서 수행합니다.

## 로컬 실행 (Node.js 22.9 이상)

```bash
npm ci
npm run build
npm start
```

브라우저에서 `http://127.0.0.1:8787`을 엽니다. 서로 다른 브라우저 또는 일반/시크릿 창에서 가입하면 Global Lounge에서 실시간 대화를 확인할 수 있습니다. 비밀번호 없는 게스트 프로필이며 같은 브라우저의 HttpOnly 쿠키로 30일간 복원됩니다. 로그아웃하거나 쿠키를 삭제하면 이전 계정으로 다시 로그인할 수 없습니다. 이름만으로 다른 계정을 재사용하지 않습니다.

### AI 연결

`.env.example`을 `.env`로 복사하고 서버 전용 설정을 입력합니다.

```dotenv
OPENAI_API_KEY=your_server_side_key
OPENAI_MODEL=gpt-4.1-mini
PORT=8787
HOST=127.0.0.1
```

서버를 재시작하면 화면에 AI 활성 상태가 표시됩니다. API 키는 브라우저 코드에 포함되지 않습니다. `VITE_` 접두사가 붙은 키 변수는 사용하지 마세요. AI 기능은 전송한 메시지와 최근 문맥을 외부 API로 처리합니다. 서버 키가 없으면 API 호출이 발생하지 않습니다.

Responses API의 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 사용합니다. 기본·문화 번역과 언어별 설명을 JSON 스키마로 받아 검증합니다. 모델은 환경변수로 변경할 수 있습니다. 문화적 해석은 문맥에 따라 달라질 수 있으며 AI 결과는 검토가 필요합니다.

### 개발

터미널 1에서 `npm run server`, 터미널 2에서 `npm run dev`를 실행합니다. Vite가 `/api`를 8787 포트로 프록시합니다. 서로 다른 origin의 개발 서버를 사용하는 경우 `.env`의 `ALLOWED_ORIGIN`에 실제 프런트엔드 origin을 지정합니다. 서버 없이 `npm run dev`를 실행하면 브라우저 모드로 시작합니다.

```bash
npm test
npm run build
```

통합 테스트는 가입·언어 분리·방 접근 권한·실시간 이벤트·영구 저장·세션 복원·로그아웃·AI 실패·대화 요약을 검증합니다. AI 응답 경로는 테스트 대역으로 검증하며 실제 AI 품질 검증에는 운영 API 키가 필요합니다.

## 배포

GitHub Pages (`https://jiwon100022.github.io/pp/`)에는 `dist/`만 올릴 수 있으므로 브라우저 모드로 실행됩니다. `main` 소스를 바꿔도 기존 `gh-pages` 배포는 자동으로 갱신되지 않습니다. Pages를 갱신하려면 빌드 후 `dist/` 전체를 `gh-pages` 루트에 반영해야 합니다.

실제 다중 사용자 + AI 서비스는 Node 서버를 실행할 수 있는 호스트에 저장소를 배포하고 `npm ci`, `npm run build`, `npm start`를 실행합니다. HTTPS 리버스 프록시 뒤에서 `HOST=0.0.0.0`, `COOKIE_SECURE=true`를 설정하고 원래 `Host` 헤더를 유지하세요. 프런트엔드와 API를 같은 origin에 제공하는 구성을 권장합니다. 별도 프런트엔드에는 빌드 시 `VITE_API_URL`(서버 origin)과 서버 `ALLOWED_ORIGIN`을 정확히 지정해야 하며 브라우저의 쿠키 정책이 적용됩니다.

단일 서버 프로토타입을 위한 JSON 저장소입니다. `data/`를 영구 볼륨으로 유지하고 백업하세요. 여러 Node 프로세스가 같은 파일을 동시에 사용하면 안 됩니다. 일반 공개 서비스 운영에는 계정 복구·멤버 초대 동의·관리 기능·데이터베이스·운영 제한을 추가해야 합니다. 현재 이름·국가·언어는 가입자 디렉터리에 표시되며 개인방 메시지는 멤버에게만 제공됩니다. API는 세션 검사, 방 접근 검사, 입력 크기 제한, 요청 제한, AI 동시 처리 제한과 origin 검사를 포함합니다.

## 구조

```text
src/        React/TypeScript UI, 다국어 라벨, 브라우저 모드
shared/     지원 언어, 국가, 예문 번역·문화 규칙·발췌 요약
server/     HTTP API, HttpOnly 세션, SSE, 저장, 서버 전용 AI 연결
tests/     서버 통합 테스트 (실제 외부 API 호출 없음)
data/       실행 시 생성되는 서버 데이터 (Git 제외)
dist/       정적 빌드 결과 (Git 제외)
```
